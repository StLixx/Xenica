# Penpot 多文件 MCP 升级

采用官方 [PR #11927](https://github.com/penpot/penpot/pull/11927) 的多会话机制，回移到本站原版 2.18.3，保留后端、导出器和数据库结构。原本考察的 develop 比稳定版多 697 个提交，构建镜像在私有 ECR，故未整体升级 develop。上游 CI 通过不等于本站体验通过。

固定基线 `ff7a66f51938b2293260ea27a64e2c4e0833b5e3`，官方功能提交 `8efbd9b5d3fc7f3b0b174efcc6c665033318dcad`。原始补丁与可直接应用于基线的兼容补丁保存在 [patches](../../deploy/penpot/patches/README.md)。兼容改动包括原版 SDK 1 的 HTTP 实测、同一官方提交中的重连策略和测试辅助文件、会话菜单中文翻译。

验收：多个文件同时连接，列举并明确选择目标，读取/修改/导出结果与目标一致，关闭或恢复标签页不再被旧连接持续独占；验证既有数据和外部图片导入。浏览器焦点变化本身不改变 Agent 所选会话。

Infra 已完成一致备份 `20261016T044603Z`，独立副本包含 1 个账号、8 个文件、3 个媒体资源。隔离恢复验证了校验值、原账号登录、原设计读取和新旧两个镜像回退；本次没有数据库迁移。原始设计、备份、凭据留在服务器私有目录。

测试：旧代码先复现会话测试失败；修复后 MCP 68 项、插件 28 项测试通过；前端 11 项、44 条断言通过；实际构建的 SDK 1 HTTP 服务通过目标路由、歧义提示、用户隔离、关闭会话拒绝和单会话兼容测试。前端定向格式与 lint 通过。全部构建与测试在 Infra 执行。

现场目录 `/opt/penpot-multi-session` 保存构建源、日志、镜像构建上下文和隔离验证报告；`/mnt/HDD/penpot/rollback/multi-session-20261016T053752Z` 保存原部署配置及镜像引用，权限受限。回退只恢复原前端和 MCP 镜像并重建这两个服务，不能覆盖运行中的用户数据。

已在原网址通过实际 ChatGPT/Codex 连接器和浏览器验证：三个文件并存、明确选择目标、无目标时列举会话、左上角连接/断开、错误文件导出拒绝、独立验收文件修改和 PNG 导出、官方头像外链显示、刷新持久化，以及 MCP 服务重启后无需点击的自动重连。详情及镜像摘要见 [实测记录](../../deploy/penpot/multi-session-evidence.json)。原 Demo 与空白文件只读；新增的验收文件为 `MCP 多会话与外链验收`。

镜像归档已保存在 Infra HDD、core 和既有 OneDrive，云端校验无差异。灾难恢复时先校验归档 SHA256，`docker image load -i` 导入，再使用记录中的镜像摘要；不可只恢复引用本地镜像的 `.env`。部署后配套备份 `20261016T072948Z` 已完成独立副本，包含新增验收文件和媒体（9 个文件、4 个媒体资源）。

使用边界：切换浏览器焦点不自动选择 Agent 目标；刷新页面需重新点击连接，ID 可能改变，Agent 应重新列举并按文件选择。真正挂起的浏览器仍须唤醒才能执行插件，不能声称服务端能替浏览器继续执行。GitHub raw 图片在 Infra 被重置连接，官方账号头像源可用，不能把某一来源网络失败归为全部外链不支持。用户交互验收仍待确认，不合并。

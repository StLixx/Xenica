# Xenica 架构文档

**本文档为 Xenica 项目的唯一可信来源**

---

## 一、灵魂

**Xenica / 织念** — 异质信息的智能连接体。

不是笔记工具，不是知识管理，是**大脑的外延**。

核心理念：你不需要"管理"信息，你只需要"使用"信息。管理的成本（分类、打标签、建链接）应趋近于零。

---

## 二、设计哲学

### 认知瞬间是唯一入口

所有信息都是同一种东西：一个认知瞬间。
在某个场景下 → 感受到/注意到某个东西 → 产生了想法或行动冲动。

不按类型分（观点/任务/错题/疑问）。类型是视角标签，不是存储结构。

### 对话后存，不是直接存

你说话 → AI 讨论/纠正/补充 → 你确认 → 精炼版存入。
存入的是经过思辨的版本，不是原始碎片。但原始碎片（朴素认知）也保留，记录认知成长轨迹。

### 对话即图谱生长

对话不是图谱的"输入工具"，对话本身就是图谱的一部分。

每次对话产生一个**局部图谱**：这次讨论涉及的节点和关系。
- 你可以浏览这个局部图谱，看这次思维怎么发展的
- 局部图谱审核后合并到**总图谱**
- 回溯任何一次对话，都能看到当时的思维进程图

```
对话 1 → 局部图谱 A ──┐
对话 2 → 局部图谱 B ──┼──→ 总图谱
对话 3 → 局部图谱 C ──┘
```

### 关联自动化

AI 自动建立关联（语义/时空/感官三种边）。
高置信度自动建立，中置信度提示确认，低置信度不做。

### 视角标签代替文件夹

同一节点可以同时是任务、认知洞察、待解答疑问、作文素材。
不同视图 = 不同滤镜，看到同一张图的不同面。

### 主动参与

AI 不只被动存储，还基于你的信息主动建议：
- 间隔重复提醒（未掌握的知识点）
- 目标对齐（当前做的事对长远目标有没有用）
- 输出生成（文章/动态/作文素材）

## 三、节点结构

一个节点可能具备以下属性（不强制全有）：

| 属性 | 说明 | 必须 |
|------|------|------|
| raw_input | 用户原话 | 是 |
| refined | 对话后精炼表述 | 否 |
| trigger | 触发源/场景 | 否 |
| timestamp | 时间 | 是 |
| location | 地点 | 否 |
| perspectives | 视角标签（多个） | 否 |
| embedding | 语义向量 | 自动生成 |
| conversation_id | 属于哪次对话 | 是 |

### 边的类型

| 类型 | 说明 | 例子 |
|------|------|------|
| semantic | 概念相关 | 具身隐喻 ↔ 认知语言学 |
| temporal | 同时/同地发生 | 骑车 ↔ 听血型 |
| sensory | 感官触发 | 听到这首歌 → 想到那个场景 |
| evolution | 认知演化 | 朴素认知 → 精炼认知 |

### 实体

从认知瞬间中提取的可复用知识点（人物/概念/作品/地点）。
实体附着在认知瞬间上，不独立创建。

## 四、技术栈

| 组件 | 选型 | 理由 |
|------|------|------|
| 后端 | Rust + Axum | 单文件部署、零运行时、编译器保证质量 |
| 数据库 | SurrealDB（嵌入式） | 图+向量+文档全合一、Rust 原生 |
| 前端 | React + TypeScript + TailwindCSS | 和 Commander CGUI 同栈 |
| 图谱可视化 | react-flow | 可编辑图，支持节点内嵌组件 |
| LLM | Claude Opus（对话）/ Sonnet（提取）/ Gemini Flash（廉价任务） |
| LLM 接口 | Antigravity API（端口 8045，OpenAI 格式） |
| 部署 | 台式机（32GB + 1TB + UPS，常开） |
| 远程 | Cloudflare Tunnel |

## 五、系统架构

```
用户（语音/文字/拍照/链接）
    ↓
输入适配层
    ↓
对话引擎（Claude Opus）
    ↓ 对话过程中实时生成局部图谱
局部图谱（本次对话的节点和边）
    ↓ 用户确认/合并
总图谱（SurrealDB）
    ↓
图谱引擎
    ├── 联想链检索（沿边遍历）
    ├── 语义搜索（向量匹配）
    └── 多视图渲染（react-flow）
    ↓
主动服务
    ├── 间隔重复提醒
    ├── 目标对齐判断
    └── 输出生成
```

## 七、不做的事

- 不商业化、不开源
- 不做游戏化包装（旧设计的叙事碎片、成就系统）
- 不做多用户
- 不考虑高并发
- 不用文件夹分类

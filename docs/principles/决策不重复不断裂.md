# 决策不重复、不断裂

一个 thread 产出的 ADR 之后，下一个 thread 对它的扩展不应该重写原 ADR，也不应该在新的 ADR 里假装上一个 thread 不存在。

两个做法：

1. **不重写**：原 ADR 状态一旦 accepted 就不修改——新决策跟在上面写 `supersedes` 或交叉引用的锚点，不改已经冻住的文本。
2. **不断裂**：新 ADR 明确声明它与哪个旧 ADR 关联，旧 ADR 末尾加一条"跨 thread 关联"指回新 ADR。两端各放一个链接——任何人顺着其中一个能找到另一个，不需要遍历整个仓库。

## 具体场景

上一个 thread 敲定了 nodes + edges 两张表。下一个 thread 加全文搜索，可以在不碰 nodes 表的前提下新增 search_index 独立表。在 search-index ADR 的 Context 里引 data-model ADR，在 data-model ADR 的 Consequences 后加"跨 thread 关联"指向 search-index ADR。两个决策各自在自己的 thread 文件夹里，通过链接结网。

这么做的核心价值：未来某天回看 data-model ADR，不用去 `decisions/` 里翻找"有没有哪个后续 thread 改了这东西"——本 ADR 末尾的链接就告诉你了。

> *来源：本项目在 architecture-foundation → core-capabilities 的 thread 交接中提炼。对应的业界概念是"可追溯性"（traceability）——但传统 traceability 强调的是需求到实现的映射，这里强调的是跨层级决策之间不互相覆盖也不互相遗忘。*

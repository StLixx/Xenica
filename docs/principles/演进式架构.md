# 演进式架构

架构不是一次性产物，是贯穿整个项目的持续努力。通过小步增量变化和持续反馈来演进架构，而不是试图在纸面上一次画对。

## 具体场景

每跑通一个 Phase，拿实际的代码行为回头审视架构——哪些假设被验证了？哪些被推翻了？在下一个 Phase 的 scope 中修正。把架构的"正确性"从"一次性命中"变成"持续校准"。

> *来源：Ford、Parsons、Kua《Building Evolutionary Architectures》——"An evolutionary architecture supports guided, incremental change as the first principle across multiple dimensions." Martin Fowler 序言——"architecture is a constant effort, one that works closely with programming so that architecture can react both to changing requirements but also to feedback from programming."*

# 0010 交付候选与验收

状态：实施中 · 2026-10-11 · 范围见 specs/54-delivery-system/spec.md。

产品验收绑定确切源码、构建产物和部署身份；工程证据另外验证。Scope 批准不能作为成果验收。规则变化使工程资格重新计算，不能改写用户历史判断。

门禁以确定候选及明确的工作流运行/尝试身份计算资格，缺失或失效证据默认阻止。合并依赖 GitHub 强制主线兼容保护，不能以“合并前读取一次主线”声称消除并发竞态。

仓库保存可检索的定义、决策和候选关联；持久设计画板与临时预览生命周期分离。上游改造记录来源和受管理的差异，不修改服务器上的临时依赖作为交付。

实施状态：构建流水线生成摘要候选；实际预览检查源码与镜像摘要，在该部署上运行浏览器回归。门禁从 GitHub 最新 job 读取运行、尝试、源码与结论，核对候选主线及规则指纹，并要求 Agent 对同一产物的全部场景与视觉实测报告通过。用户验收记录绑定产品身份（源码、产物、预览），相同产品重跑工程检查不会改写体验判断；产物改变须重新体验。

当前仍为草稿：首次上线部署器、平台严格主线保护、正式唯一画板数据迁移及整套交付验证必须完成后才能宣称闭环。流水线候选构件不是永久档案；仓库保存定义、决策、实现和证据入口，画板正文/历史/原图由正式数据库与可迁移档案保留。

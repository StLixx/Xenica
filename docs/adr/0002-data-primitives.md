# 0002 数据原语

状态：已采纳（骨架只实现了节点、关系、痕迹）· 2026-10

## 决定

核心只认五种原语：

| 原语 | 是什么 |
|---|---|
| 节点 | 一切内容的单位：一页 PDF、一个块、一道题、一个知识点、一项设置 |
| 关系 | 两个节点之间带类型的有向边（包含、引用、派生……） |
| 锚点 | 指向原文某处，用 W3C Web Annotation 的选择器（文本位置、引用片段、页码区域） |
| 位置 | 节点在某个视图里的布局信息，属于视图而不属于节点 |
| 痕迹 | 每次写入的记录：谁（用户或某个版本的处理器）、做了什么、前后差异。只增不改 |

两种机制：

- **视图**：用某种方式看同一批节点和关系（列表、图、阅读器、融合视图）。
- **处理器**：采集（导入 PDF）、加工（拆块、提取知识点）、产出（导出、出题）。处理器的输出都是带痕迹的节点和关系。

同一份资料的不同格式（PDF、MinerU 提取的 Markdown、OCR 文本）各是一个节点，用「派生」关系相连；视图负责把它们合并显示。

## 九条规则

1. 原始不可变，派生可重算。原始资料只读；派生物记下来源和处理器版本，能删了重算。
2. AI 只提议，人裁决。AI 的产出先进收件箱，确认后才成为正式节点。
3. 结构是视图不是存储。不存树，只存节点和关系。
4. ID 全局唯一、可离线生成（UUID v7）。将来离线编辑、多端合并不用改 ID。
5. 核心只认原语，内置功能也走插件接口。这样插件接口一直被真实使用，不会烂。
6. 插件先声明再加载。manifest 写明它要读写什么，核心按声明授权。
7. 配置也是知识。任何设置项（包括别的软件的）都是一个节点，带来源锚点、版本和痕迹，放在系统空间。只有启动所需的最少配置留在环境变量/文件里。
8. 自己的设置必须带预览或示例，并说明影响什么。
9. 密钥不进图，只进密钥库。

## 后果

- 每次写入都要同事务写痕迹，由 `Store` 统一负责（`crates/store`）。
- 痕迹表在数据库层禁止 UPDATE/DELETE（触发器）。
- 新功能先问：它是哪种原语的组合？如果需要第六种原语，先写 ADR。

# 0007 鉴权

状态：已采纳 · 2026-10

## 决定

- **用户名 + 密码，会话放 Cookie。** `xenica_session`：HttpOnly、Secure、SameSite=Lax，30 天。库里只存令牌的 SHA-256 和 Argon2id 密码哈希（`users`、`sessions` 两张表，不是节点——规则 9）。
- **默认受保护。** 鉴权中间件包住整个 `/api`，只放行 `/api/health` 和 `/api/auth/*`。新接口不用记得加；handler 要知道是谁就写参数 `user: CurrentUser`，痕迹记成 `user:<id>`。
- **首次设置用设置码。** 库里没有账号时，服务启动在日志里打印一次性设置码；没有它谁也建不了号，避免「谁先打开谁当主人」。用过即失效，重启换新。
- **防暴力尝试。** 同一用户名连续输错 5 次锁 15 分钟（进程内计数）。用户名不存在时也算一次哈希，响应时间一样。
- **防跨站写。** 会改数据的请求带了 `Origin` 就必须和 `Host` 一致——SameSite 挡不住同一根域名下的 PR 预览站。
- **预览站有示例账号。** `XENICA_SEED=demo` 时建 `demo` / `demo`，登录页直接提示；预览里只有示例数据。

## 理由

- 只有一个用户，密码最简单，手机、电脑、任何浏览器都能用；不依赖第三方（GitHub 登录要先建 OAuth 应用，国内网络也不稳）。
- Cookie 而不是 Bearer 令牌：前端拿不到令牌，XSS 偷不走；同源请求浏览器自动带上，不用改前端的每个请求。

## 后果

- 锁定计数在内存里，重启清零；攻击者也能用错误密码把你锁 15 分钟——单用户可以接受，以后真遇到再按 IP 限速。
- 只有 https 或 localhost 能登录（Secure Cookie）。
- 以后再做：通行密钥、多用户与空间（#9）、修改密码（暂时用 `docker compose exec db psql` 删 `users` 行后重新设置）。

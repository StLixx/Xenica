# 0008 块即节点

日期：2026-10-08 · 状态：采纳（v0.2.0）

## 背景

用户整理课程笔记：边听课边截图粘贴、随手写几句、写公式，之后再把公式、方法整理出来。Notion/Obsidian 要先给页面起名、先建数据库再一条条填，Jira 式的固定属性更重。目标是「工具适应人」：先随手记，结构以后再长出来。

## 决定

- **一块 = 一个节点。** 页也是节点，用「包含」关系（`contains`，带顺序 `edges.pos`）按顺序装着块。任何节点都可以有子节点，层数不限。
- **标题可以为空。** 界面用正文第一行代替；没有正文的页用它的第一块。
- **正文是 Markdown**（`body.md`），公式用 `$…$`、`$$…$$`（KaTeX）。
- **属性就是节点。** 正文里写 `#必备` 或 `[[积分公式表]]`，存储层在同一事务里把「提到」关系（`mentions`）同步成和正文一致，没有同名节点就新建。规则在 `crates/core/src/refs.rs`，前端渲染用同样的规则。
- **看法固定几种**：文档、列表、表格、画廊，对任意一组节点都能用，不需要先「建数据库」。打开一个节点，下面就是提到它的所有节点。
- **客户端生成 ID**（UUID v7），编辑器不等服务器就能接着写；写操作按顺序排队。
- **截图存进库**（`files` 表，按 sha256 去重，不可变），用 `/api/files/{id}` 引用。

## 后果

- 删除页会连带删除它包含的块（痕迹保留）。
- 改标记名会留下没人提到的旧节点，以后再做清理。
- 文字叠层（MinerU）、AI 识别、输出（考前清单等）、在图上框选都留给后续版本。

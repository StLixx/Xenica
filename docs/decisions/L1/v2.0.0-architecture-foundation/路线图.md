# 开发路线图

## Phase 1 — Make it work

> 目标：用户能通过 CLI 创建节点和边、查看单个节点及其邻居、查看全局图谱概览。
> 对应场景：S1 + S7 + S6

### Step 1: 项目骨架

- `cargo init` 初始化 Rust 项目
- 声明依赖：`axum`、`sqlx`（features: postgres, runtime-tokio, uuid, chrono）、`tokio`、`serde` / `serde_json`、`uuid`、`chrono`、`clap`（CLI 参数解析）
- 搭建目录结构（`src/main.rs` + `src/db.rs` + `src/handlers.rs` + `src/models.rs`）

### Step 2: 数据库 migration

- 写第一份 migration：创建 `nodes` 和 `edges` 两张表 + 两个索引（`idx_edges_source`、`idx_edges_target`）
- 跑 migration，连接本地 PostgreSQL 验证

### Step 3: Rust 数据模型

- 定义 `Node` 和 `Edge` 结构体（含 serde 序列化）
- 实现 sqlx 读写函数：`create_node`、`get_node`、`get_neighbors`、`list_nodes`、`list_edges`

### Step 4: API 路由

- Axum 定义 5 个端点（见 [api-design.md](api-design.md)）
- 统一错误响应格式
- 接 sqlx 查询

### Step 5: CLI 客户端

- 用 clap 定义子命令
- `xenica create "内容" --connect <id1> --connect <id2>` → S1
- `xenica show <id>` → S7
- `xenica neighbors <id>` → S7
- `xenica list` → S6
- CLI 调 API，格式化输出

### Step 6: 集成测试

- 创建节点 → 连边 → 查邻居 → 验证返回的邻居数量和边 label
- 全量 list → 验证节点和边都在

### 验收标准

端到端走通 S1 → S7 → S6：

```bash
# S1: 录入并连接
xenica create "Rust 的所有权机制" --connect <rust节点ID>

# S7: 聚焦探索
xenica show <新节点ID>
xenica neighbors <新节点ID>
# 输出：该节点连接到了 "Rust"（边 label 由用户创建时指定）

# S6: 全局视图
xenica list
# 输出：所有节点和边的列表
```

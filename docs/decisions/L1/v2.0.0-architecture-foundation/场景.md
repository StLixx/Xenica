# 使用场景

> 提炼自 `docs/genesis/背后的问题.md`。以用户动作为主语，不涉及技术实现。

## Phase 1 — make it work

以下三个场景是 Xenica 最核心的原子能力。没有它们，其他所有场景都跑不起来。

### S1 · 知识录入与连接

用户在阅读教材、思考或做笔记时，想把一段文字存入系统，并将它连接到已有的知识节点上。

- 用户输入一段文本（教材段落、个人想法、引用……）
- 用户指定这段文本与哪个（些）已有节点相关联
- 系统保存这段文本，建立它到指定节点的连接

### S7 · 聚焦式节点探索

用户选中某个节点，查看它连接到了哪些其他节点。

- 用户聚焦于一个节点
- 系统展示该节点直接关联的所有邻居节点，以及每条连接的含义
- 用户从邻居节点中继续进入下一个节点，反复此过程

### S6 · 知识图谱导航与定位

用户查看自己的全局知识版图，了解已经触达了哪些区域、当前关注点在整个版图中的位置，判断自己有没有偏离学习方向。

- 用户打开全局视图
- 系统展示节点之间的网状关系概览
- 用户感知到自己在知识版图中的当前位置和覆盖范围

## Phase 2+ — 建立在核心之上的增值场景

### S2 · 视频时间戳关联

用户在看网课视频时，想把某个时间段的内容连接到课件节点或知识节点上。用户标记视频的起止时间点，系统将这个片段关联到指定节点。

### S3 · AI 对话节点化

用户与 AI 进行多轮对话时，想知道自己从哪个问题出发、经历了哪些分支、最终到达了什么结论。对话自动节点化，形成一棵可见的对话树。

### S4 · 代码 ↔ 理论追溯

用户在写代码时，想从某个函数追溯它背后的理论来源——某本书、某门课、某个工程原则。函数作为一个节点，连接到它的理论根基。

### S5 · 课程资源自动采集

用户发现一门高质量课程（如 MIT 公开课）——课件、题目、代码仓库、视频全部公开。用户希望自动爬取并预建节点结构，直接上手学。

### S8 · 跨格式知识同一性

用户发现视频片段、书籍段落、随口大白话实际上在说同一件事。用户将它们标记为"同一知识"，系统记录这种跨格式的等价关系。

### S9 · 完成事项的回响

用户将一个 TODO 标记为完成。将来某天，用户可能想把这个已完成的事项连接到新的场景或知识上。完成不是终点——已经完成的东西可以被新的思考重新激活。

### S10 · 信息边界可视化

用户查看自己已经触达了哪些知识区域、相邻的未探索区域在哪，直观感受到知识版图的扩展和组织带来的价值感。

---

## 场景分层理由

Phase 1 选 S1 + S7 + S6，是因为：

- **S1 是"写"**——没有存东西和连东西的能力，其他全是空谈
- **S7 是"读一个"**——存了之后要能看。查节点、看邻居是最基础的读操作
- **S6 是"读全局"**——S7 是显微镜，S6 是导航图。两者互补，覆盖最基本的两个认知视角

Phase 2+ 的场景都依赖 Phase 1 的核心能力。其中 S2、S3、S5 还需要额外的基础设施（异步处理、外部爬取），不应在 Phase 1 引入。

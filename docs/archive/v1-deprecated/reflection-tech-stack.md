## 四、技术调研关键结论

| 主题 | 结论 |
|------|------|
| 图数据库 vs RDB | 图数据库的图像遍历快，但搜索算法、生态远不如 RDB。许多图算法（如 PageRank）在图数据库上反而跑不动。所有图结构都可以用 RDB 的节点表+边表表达 |
| Xenica 是否需要图算法 | **是**。PageRank（节点重要性）、最短路径（联想链）、社区发现、中心度分析等 |
| PostgreSQL vs MySQL | MySQL 长期落后于 SQL 标准（递归 CTE、窗口函数、JSON 函数、扩展机制均弱于 PG） |
| PostgreSQL vs MongoDB | MongoDB 早期不完整支持 ACID，被大量程序员当"JSON 版 Excel"用，忽视数据库核心功能 |
| 是否需要 HBase | **不需要**。PostgreSQL JSONB + GIN 索引 + 分区表足够覆盖异构数据需求 |
| 当前 SQLite 的问题 | JSON 无索引加速、中文全文搜索弱、向量搜索生态不如 pgvector 成熟 |

### ACID 特性

IBM 最早在关系型数据库中定义的四条铁律：

- **A (Atomicity 原子性)**：操作要么全做、要么全不做（如转账：扣钱+加钱必须同时成功或同时失败）
- **C (Consistency 一致性)**：数据永远遵守预设规则（如"余额不能为负"）
- **I (Isolation 隔离性)**：多人同时操作互不干扰
- **D (Durability 持久性)**：数据写入后永不丢失，断电重启也不丢

> MongoDB 早期只做到了 D，A/C/I 都没有完整支持，直到 2018 年的 4.0 版本才补上多文档事务。PostgreSQL 从诞生起就完整实现了 ACID。

## 五、推荐的 PostgreSQL 技术方案

```
PostgreSQL 18
├── pgvector        → 向量/语义搜索
├── Apache AGE      → 原生 Cypher 图查询（按需启用）
├── pg_trgm         → 模糊文本搜索
└── 递归 CTE        → 图遍历（PageRank、联想链、最短路径）
```

Rust 侧使用 `sqlx`（编译期 SQL 验证），与当前 SQLite 代码架构几乎不变。
